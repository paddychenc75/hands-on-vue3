::: terms
类型推导
: TypeScript 根据初始值或返回值自动得出类型，不需要手写。

vue-tsc
: 能检查 `.vue` 文件类型的命令行工具。它把 `.vue` 转成 TypeScript，再调用 TypeScript 检查。

项目引用
: 一个 `tsconfig.json` 通过 `references` 指向几个子配置，每个子配置管一部分文件。

泛型组件
: props 的类型由使用者决定的组件。

模块扩充
: 用 `declare module 'vue'` 给 Vue 已有的接口增加字段，例如全局属性。

编译宏
: 编译器在构建时替换的函数，例如 defineProps。
:::

::: why
子组件的 `size` 只支持 `'sm'` 和 `'lg'`。你传了 `size="xl"`，页面不报错，只是样式不对。你把 `emit('move', 'archived')` 写进了代码，没人告诉你状态里没有 `archived`。

原因：Vite 只把类型删掉，不检查类型。JavaScript 在运行时也不检查。错误一路通过，到用户手里才暴露。

本章教你三件事：让项目检查类型，给 Vue 的各种东西写类型，读懂检查报出的错。后面的 Pinia、Router、测试和项目章都默认你会写这些类型。
:::

本章的命令和报错都在 `npm create vue@latest` 新建的 TypeScript 项目里实测：Vue 3.5.43，TypeScript 6.0.3，`vue-tsc` 3.3.12。

### 14.1 让项目检查类型

在 `<script setup>` 上加 `lang="ts"`，这个组件就可以写类型：

```vue
<script setup lang="ts">
const count: number = 'x'   // 类型错误
</script>
```

但 `npm run dev` 不会报这个错。Vite 用转译器逐个文件删除类型，不检查。检查由两个工具做：

- **编辑器**。VS Code 装 **Vue - Official**（扩展 id 是 `Vue.volar`，脚手架的 `.vscode/extensions.json` 会推荐它；旧的 Vetur 要停用）。它在你输入时检查 `<script>` 和 `<template>`，补全 props 和事件名。WebStorm 自带支持。
- **`vue-tsc`**。命令行检查，用在构建和 CI 里。

脚手架生成的 `tsconfig` 用**项目引用**，分成三个文件：

| 文件 | 管什么 |
|---|---|
| `tsconfig.json` | 自己 `files: []`，不含任何文件，只用 `references` 指向另外两个 |
| `tsconfig.app.json` | `src/` 下的浏览器代码和 `env.d.ts`，继承 `@vue/tsconfig` |
| `tsconfig.node.json` | `vite.config.ts` 等在 Node 里运行的配置文件 |

拆开是因为两边的全局类型不同：浏览器代码有 `document`，配置文件有 `process`。

与 Vue 有关的几个选项，大部分来自 `@vue/tsconfig`：

| 选项 | 作用 |
|---|---|
| `strict` | 开启严格检查。没写类型的参数会报错（隐式 any） |
| `verbatimModuleSyntax` | 只当类型用的导入必须写 `import type`。Vite 逐个文件转译，必须知道哪些导入可以删除 |
| `noUncheckedIndexedAccess` | 脚手架额外加的。`list[0]` 的类型是 `T \| undefined` |
| `paths` | 路径别名（`@/*`），要和 `vite.config.ts` 里的 `alias` 一致 |

`env.d.ts` 里的 `/// <reference types="vite/client" />` 提供 `import.meta.env` 和图片等资源导入的类型。在它旁边写 `interface ImportMetaEnv { readonly VITE_API_URL: string }`，就能给自己的环境变量加类型。注意 Vite 的 `ImportMetaEnv` 带索引签名，所以拼错的变量名仍然不报错。

**该运行哪条命令？** 看项目有没有项目引用：

| 项目结构 | 命令 | 说明 |
|---|---|---|
| 脚手架（根 `tsconfig.json` 是 `files: []` 加 `references`） | `vue-tsc --build`，即 `npm run type-check` | `npm run build` 会并行运行它 |
| 同上，只想检查浏览器代码 | `vue-tsc --noEmit -p tsconfig.app.json` | 指定子配置 |
| 只有一个 `tsconfig.json`、没有 `references` | `vue-tsc --noEmit` | 单文件配置的小项目、组件库 |

在脚手架项目的根目录运行 `vue-tsc --noEmit`，**不会检查任何文件，也不报错，退出码是 0**：根配置没有文件。看到“通过”不等于代码没问题。

脚手架把 TypeScript 固定在 `~6.0.0`。`vue-tsc` 3.3.12 与 TypeScript 7.0.2 不兼容，运行时抛出 `ERR_PACKAGE_PATH_NOT_EXPORTED`（第 41 章详细解释）。不要单独升级 TypeScript 的主版本。

### 14.2 为 props 和事件声明类型

在 `defineProps` 和 `defineEmits` 的尖括号里写类型，用法见[第 6 章](/chapters/06-comm)。类型写在单独的文件里，用 `import type` 导入：

```ts
// types.ts
export type Status = 'todo' | 'doing' | 'done'
```

```vue
<script setup lang="ts">
import type { Status } from './types'

const { title, status = 'todo', tags = [] } = defineProps<{
  title: string
  status?: Status
  tags?: string[]
}>()
const emit = defineEmits<{
  move: [to: Status]   // emit('move', 'done')
  remove: []
}>()
</script>
```

下面是三个要点。

**默认值。**3.5 起直接在解构里写默认值。数组和对象的默认值编译器会自动包成函数。3.4 及以前写 `withDefaults(defineProps<Props>(), { tags: () => [] })`，这时数组和对象要自己写成函数。`withDefaults` 在 3.5 仍然可用。解构出来的变量不能直接传给 `watch`，要写 getter：`watch(() => status, …)`。直接传会得到 `TS2769: No overload matches this call`。

**导入的类型。**3.3 起可以导入类型、继承接口、用 `Pick`、`Partial`、`&`。实测这些都能编译。唯一的限制：编译器只分析语法，不计算类型。所以整个 props 对象不能写成条件类型。这个错 **`vue-tsc` 不报**，而是 `vite build` 时由编译器报 `Unresolvable type: TSConditionalType`。单个 prop 可以用条件类型，但它的运行时 `type` 会变成 `null`，不做运行时检查。

**事件。**对象写法 `move: [to: Status]` 是 3.3 起的简写。旧的调用签名写法 `(e: 'move', to: Status): void` 仍然可用，读旧代码时会遇到。带类型的 `emit` 同时检查事件名和参数。父组件里 `@move="(to) => …"` 的参数 `to` 自动得到 `Status`。

读旧代码时还会遇到运行时声明加 `PropType`：`type: Object as PropType<Task>`。它只在运行时对象写法里需要，新代码用类型声明即可。类型参数和运行时对象不能同时写。

### 14.3 v-model、插槽和模板 ref

**`defineModel`。**用类型参数声明 v-model 的类型。不写 `required` 也不写 `default` 时，值的类型包含 `undefined`：

```ts
const note = defineModel<string>()                          // string | undefined
const owner = defineModel<string>('owner', { required: true })  // string
const due = defineModel<string>('due', { default: '' })     // string
```

**`defineSlots`。**给插槽声明参数的类型。父组件的 `#default="{ status }"` 里，`status` 因此有类型。可选插槽的名字后面加 `?`：

```vue
<script setup lang="ts">
import type { Status } from './types'
defineSlots<{
  default(props: { status: Status }): unknown
  footer?(): unknown
}>()
</script>
```

**模板 ref。**3.5 的 `useTemplateRef` 配合 Vue - Official 2.1 以上，能按 `ref` 所在的元素自动推导类型。写 `useTemplateRef('inp')`，`<input ref="inp">` 对应 `HTMLInputElement`。实测对子组件也有效。推导不出来的少数情况才手写 `useTemplateRef<HTMLInputElement>('el')`。

值的类型总是带 `| null`：挂载之前是 `null`，被 `v-if` 卸载后又变回 `null`。所以访问时用可选链：

```ts
const input = useTemplateRef('inp')
onMounted(() => input.value?.focus())
```

子组件通过 `defineExpose` 决定父组件能访问什么。需要手写子组件实例的类型时，用 `InstanceType<typeof Child>`：

```ts
const modal = useTemplateRef<InstanceType<typeof MyModal>>('modal')
modal.value?.open()   // open 来自子组件的 defineExpose
```

### 14.4 ref、reactive、computed 和事件处理函数

原则：**推导优先**。初始值能说明完整类型时不手写。初始值说不全时才标注：

| 写法 | 类型 | 什么时候标注 |
|---|---|---|
| `ref(0)` | `Ref<number>` | 不用 |
| `ref(null)` | `Ref<null>` | 之后要放别的值：`ref<User \| null>(null)` |
| `ref([])` | `Ref<never[]>` | 要放元素：`ref<Task[]>([])` |
| `ref<number>()` | `Ref<number \| undefined>` | 没有初始值时，类型自动加 `undefined` |
| `reactive({ a: 1 })` | `{ a: number }` | 用接口标注变量：`const book: Book = reactive({…})` |
| `computed(() => …)` | 由返回值推导 | 返回值复杂或想固定：`computed<number>(…)` |

`reactive` 不要用泛型参数：它的返回类型会展开嵌套的 ref，和你传入的泛型不是同一个类型。

**事件处理函数。**没有类型的参数在 `strict` 下是隐式 any，会报错。原生事件的参数写 `Event`。`event.target` 的类型是 `EventTarget | null`，没有 `value`，要先断言成具体的元素：

```ts
function onInput(e: Event) {
  text.value = (e.target as HTMLInputElement).value
}
```

在模板里写内联处理函数时，只要脚本是 `lang="ts"`，也能写断言：`@input="text = ($event.target as HTMLInputElement).value"`。需要更具体的事件时用 `MouseEvent`、`KeyboardEvent`。输入框的值通常直接用 `v-model`，不用手写这个处理函数。

### 14.5 组合式函数和 provide/inject

**组合式函数的参数。**调用方可能传普通值、ref 或 getter。用 `MaybeRefOrGetter<T>`（它等于 `T | Ref<T> | (() => T)`），函数里用 `toValue` 读取：

```ts
import { watchEffect, toValue } from 'vue'
import type { MaybeRefOrGetter } from 'vue'

export function useTitle(title: MaybeRefOrGetter<string>) {
  watchEffect(() => { document.title = toValue(title) })
}
```

只接受 ref 或普通值时，用 `MaybeRef<T>`。**返回值让 TypeScript 推导**。只有想限制调用方时才标注，例如返回 `Readonly<Ref<T>>`，调用方就不能给 `.value` 赋值（本章本地任务 3 就做这件事）。

<Exercise id="maybeRefGetter" />

**provide/inject。**用 `InjectionKey` 把 key 和值的类型绑在一起。key 放在单独的文件里，两边导入：

```ts
// keys.ts
import type { InjectionKey, Ref } from 'vue'
export const ThemeKey: InjectionKey<Ref<'light' | 'dark'>> = Symbol('theme')
```

```ts
provide(ThemeKey, theme)       // 类型不对会报错
const t = inject(ThemeKey)     // Ref<'light' | 'dark'> | undefined
```

`inject` 的结果可能是 `undefined`，因为也许没有祖先 provide 过。三种处理方式：

1. **给默认值**：`inject(ThemeKey, ref('light'))`，结果不含 `undefined`。
2. **封装成 `useTheme()`，注入不到就抛错**。调用方得到不含 `undefined` 的类型，使用错误在出错的地方就说清楚。组件库里常用这个。
3. **断言**：`inject(ThemeKey)!` 或 `as`。不推荐。它只是让编译器闭嘴，缺失的问题变成运行时才发现。

用字符串当 key 时，`inject('theme')` 的类型是 `unknown`，要自己标注。所以优先用 `InjectionKey`。

### 14.6 泛型组件

列表、下拉框这类组件不知道使用者传什么数据。`<script setup>` 的 `generic` 属性声明类型参数，3.3 起可用：

```vue
<script setup lang="ts" generic="T extends { id: number }">
defineProps<{ items: T[]; selected?: T }>()
const emit = defineEmits<{ pick: [item: T] }>()
defineSlots<{ item(props: { item: T; index: number }): unknown }>()
</script>
```

使用时 T 由传入的 `items` 推导。`@pick` 的参数和 `#item` 的 `item` 都是使用者的类型，比如 `User`。`extends { id: number }` 是约束：传入没有 `id` 的对象会报错，有 `id` 的对象其余字段都保留。更多泛型组件的设计见[第 34 章](/chapters/34-patterns)的 34.7 节。

泛型组件有一个限制：它不是一个类，`InstanceType<typeof List>` 会报错（`TS2344`，不满足 `abstract new (...args: any) => any`）。取它的实例类型要用 14.7 的 `ComponentExposed`。

### 14.7 工具类型和类型扩充

先看这些类型从哪个包导入。导错包是常见的第一个报错：

| 类型 | 来自 | 用途 |
|---|---|---|
| `PropType<T>` | `vue` | 运行时 props 声明里标注类型 |
| `MaybeRef`、`MaybeRefOrGetter` | `vue` | 组合式函数的参数 |
| `InjectionKey<T>` | `vue` | provide/inject 的 key |
| `ExtractPublicPropTypes<T>` | `vue` | 从运行时 props 对象得到父组件能传的类型 |
| `ComponentInstance<typeof C>` | `vue` | 组件实例类型 |
| `ComponentProps`、`ComponentEmit`、`ComponentSlots`、`ComponentExposed` | **`vue-component-type-helpers`** | 取组件的 props、事件、插槽、暴露内容的类型 |

最后一行**不在 `vue` 里**。`import type { ComponentProps } from 'vue'` 会得到 `TS2305: Module '"vue"' has no exported member 'ComponentProps'`。先 `npm i -D vue-component-type-helpers`（它和 `vue-tsc` 来自同一个仓库）。事件那个叫 `ComponentEmit`，单数。`ComponentProps` 的结果包含 v-model 的 prop 和 `onMove` 这样的事件处理 prop。它们在第 41 章做组件库时会用到。

**类型扩充。**给 Vue 已有的接口增加字段，用 `declare module 'vue'`。例如全局属性和全局组件：

```ts
// src/types/vue-augment.d.ts
import type TaskCard from '@/components/TaskCard.vue'

declare module 'vue' {
  interface ComponentCustomProperties {
    $t: (key: string) => string   // app.config.globalProperties.$t
  }
  interface GlobalComponents {
    TaskCard: typeof TaskCard      // app.component('TaskCard', …) 注册的全局组件
  }
}
export {}
```

**文件里必须有顶层的 `import` 或 `export`。**没有的话，`declare module 'vue'` 不是扩充，而是替换了整个 `vue` 的类型，项目里所有 `import { ref } from 'vue'` 都会报 `Module '"vue"' has no exported member 'ref'`（实测）。文件还要被 `tsconfig.app.json` 的 `include` 覆盖，放在 `src/` 下即可。

路由 `meta` 的类型扩充（`RouteMeta`）见[第 17 章](/chapters/17-router)，Pinia 的类型扩充见[第 16 章](/chapters/16-pinia)。机制与上面相同。

### 14.8 读懂类型报错

`vue-tsc` 的报错格式是：

```
src/Foo.vue(4,19): error TS18047: 'el.value' is possibly 'null'.
```

按这个顺序读：

1. **位置**。`文件(行,列)`。行号是 `.vue` 文件里的行号，模板里的错误也一样。
2. **错误码和第一句**。`TS18047` 可以直接搜索。
3. **谁是“给的”，谁是“要的”**。`Type 'A' is not assignable to type 'B'` 里，A 是你写的，B 是声明要求的。
4. **长报错看最后一行**。嵌套的报错最内层那一行才是根本原因。
5. **判断哪一边错了**：调用方传错了，还是声明本身写窄了。

不要用 `as any`、`!` 或 `// @ts-ignore` 当修复。它们让错误消失，但错误指出的问题还在。

下面是 Vue 项目里最常见的六个报错（都是真实输出）：

| 报错 | 原因 | 改法 |
|---|---|---|
| `TS18047: 'el.value' is possibly 'null'.` | 模板 ref 挂载之前是 `null` | `el.value?.focus()`，或先 `if (el.value)` 判断 |
| `TS18048: 'theme' is possibly 'undefined'.` | `inject` 可能注入不到 | 给默认值，或封装成抛错的 `useTheme()`（14.5） |
| `TS2322: Type '"xl"' is not assignable to type '"sm" \| "lg" \| undefined'.` | 模板里给 prop 传了声明里没有的值 | 改调用方；确实需要 `xl` 才扩大声明里的联合类型。漏传必填 prop 时是同类的 `Property 'label' is missing in type '{ size: "sm"; }' but required in type …` |
| `TS2339: Property 'value' does not exist on type 'EventTarget'.` 同时有 `TS18047: 'e.target' is possibly 'null'.` | `Event.target` 的类型太宽 | `(e.target as HTMLInputElement).value`（14.4）。没写参数类型会得到 `TS7006: Parameter 'e' implicitly has an 'any' type.` |
| `TS1484: 'Task' is a type and must be imported using a type-only import when 'verbatimModuleSyntax' is enabled.` | 只当类型用的导入没写 `type` | `import type { Task } from './types'`，或 `import { type Task, … }` |
| `TS2345: Argument of type '1' is not assignable to parameter of type 'never'.` | `ref([])` 推导成 `never[]`，什么都放不进去 | `ref<number[]>([])` |

另外两个出现在 14.2 的报错，读法一样。`emit('move', 'archived')` 得到 `TS2345: Argument of type '"archived"' is not assignable to parameter of type 'Status'`。把解构的 prop 直接传给 `watch` 得到 `TS2769: No overload matches this call`。

改到没有报错之后，把检查放进流程：`npm run build` 已经并行运行 `type-check`，CI 里运行它即可。

### 14.9 本地任务：给组件、列表和组合式函数写类型

页面里的练习台没有类型检查器，所以这三个任务在你自己的项目里做。检查的是**类型**，不是页面效果。

**准备。**运行 `npm create vue@latest`，选择 TypeScript，进入目录 `npm install`。把下面的起始代码放进 `src/`。每个任务的验收命令都是 `npm run type-check`。

每个任务的“起始代码”故意让 `type-check` 失败。你的工作是改类型，直到它通过。

**任务 1：给无类型的组件补上 props、emits 和 slots 的类型。**

```vue
<!-- src/t1/TaskCard.vue -->
```

```ts
// src/t3/useDebounced.ts
import { shallowRef, watch, toValue, onScopeDispose } from 'vue'

export function useDebounced(source, ms = 200) {
  const out = shallowRef(toValue(source))
  let timer
  watch(() => toValue(source), (v) => {
    clearTimeout(timer)
    timer = setTimeout(() => { out.value = v }, ms)
  })
  onScopeDispose(() => clearTimeout(timer))
  return out
}
```

### 14.10 编译宏：构建时被替换的函数

`defineProps`、`defineEmits`、`defineModel`、`defineExpose`、`defineSlots` 是**编译宏**。它们只能出现在 `<script setup>` 里，运行时并不存在。所以不需要 import；import 它们反而会得到警告：`defineProps is a compiler macro and no longer needs to be imported`。

<Figure caption="编译器在构建时把 defineProps 和 defineEmits 替换为 props 和 emits 选项。运行时没有这两个函数。">
<MacroCompileTransform />
</Figure>

这解释了前面的几个现象。类型参数能生成运行时检查，是因为编译器读了你写的类型。整个 props 不能是条件类型，是因为编译器只读语法，不算类型。`vue-tsc` 检查类型，编译器生成选项，两者各管一件事，所以一个通过另一个仍可能失败。`.vue` 文件整体怎样被编译，见[第 29 章](/chapters/29-compiler)的 29.6 节。

::: summary
- 删除类型的是 Vite，检查类型的是编辑器（Vue - Official）和 `vue-tsc`。脚手架项目用项目引用，类型检查用 `vue-tsc --build`；只有单个 `tsconfig.json` 才用 `--noEmit`。
- props 和事件用类型参数声明：`defineProps<{…}>()`、`defineEmits<{ move: [to: Status] }>()`。3.5 起用解构写默认值。3.3 起可以导入类型，只有“整个 props 是条件类型”不行。
- `defineModel<T>()` 在没有 `required` 和 `default` 时带 `undefined`。`defineSlots` 给插槽参数类型。模板 ref 的值总带 `null`，用可选链。
- 推导优先：初始值说不全（`null`、`[]`）才标注。事件处理函数写 `(e: Event)`，用断言取具体元素。
- 组合式函数的参数用 `MaybeRefOrGetter<T>` 加 `toValue`。`inject` 可能是 `undefined`：给默认值，或封装成抛错的 `useXxx`。
- 泛型组件用 `generic="T extends …"`。`ComponentProps`、`ComponentEmit`、`ComponentSlots`、`ComponentExposed` 来自 `vue-component-type-helpers`，不来自 `vue`。
- 读报错：看位置，看“给的”和“要的”，长报错看最后一行，判断哪一边错了。不要用 `as any` 或 `!` 当修复。
- 编译宏在构建时被替换成 props 和 emits 选项，所以不需要 import。
:::
