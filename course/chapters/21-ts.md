### 21.1 编译宏：构建时被替换的函数

编译宏是编译器在构建时替换的函数，例如 defineProps、defineEmits、defineModel、defineExpose 和 defineSlots。编译宏只能在 `<script setup>` 中使用。编译宏在运行时不存在，所以不需要 import。

### 21.2 为 props 和事件声明类型

在 defineProps 和 defineEmits 的尖括号中写类型：

```ts
const props = defineProps<{ title: string; size?: 'sm' | 'md' }>()
const emit = defineEmits<{ close: [] }>()
```

**场景：任务卡片的 props 和事件。**状态只能是三个值之一。用字面量联合类型声明它。传入其他值时，编辑器报错。用具名元组声明事件参数。`emit` 的事件名和参数都有检查。

```vue
<script setup lang="ts">
type Status = 'todo' | 'doing' | 'done'
const { title, status = 'todo' } = defineProps<{   // 3.5+：解构并写默认值
  title: string
  status?: Status
}>()
const emit = defineEmits<{
  move: [to: Status]   // emit('move', 'done')
  remove: []
}>()
</script>
```

注意两点：

1. 不要同时传类型参数和运行时对象，例如 `defineProps<{ a: string }>({ a: String })`。编译器报错。选择一种写法。
2. 3.5 中解构的 prop 不能直接传给 watch，编译器会报错。写 getter：`watch(() => status, …)`。

下面两道练习做编译器做的那一步：把类型改写为运行时的 props 声明。

### 21.3 为 v-model 声明类型：defineModel

defineModel 的用法见[第 5 章](/chapters/05-comm)。这里只说明类型。用类型参数声明 v-model 的类型。

**场景：负责人选择器支持 v-model。**必填时写 `required: true`，类型中就没有 undefined。命名的 v-model 写在第一个参数。

```vue
<script setup lang="ts">
const owner = defineModel<string>({ required: true })            // Ref<string>
const due = defineModel<string | null>('due', { default: null })  // v-model:due
</script>

<!-- 使用 -->
<OwnerPicker v-model="task.owner" v-model:due="task.due" />
```

注意：不写 required 也不写 default 时，类型是 `Ref<string | undefined>`。

### 21.4 为 ref、模板 ref 和 provide/inject 声明类型

ref 通常自动推导类型。初始值为 null 时，写出完整的类型：

```js
import type { Ref, InjectionKey } from 'vue'

const count = ref(0)                          // Ref<number>
const user = ref<User | null>(null)           // 不写类型时是 Ref<null>
```

**场景：页面打开后聚焦输入框。**3.5 及以上用 useTemplateRef 读取模板 ref。元素在挂载后才存在，所以值可能是 null：

```ts
const inputEl = useTemplateRef<HTMLInputElement>('input')   // 模板：<input ref="input">
onMounted(() => inputEl.value?.focus())
```

**场景：主题在多层组件中共享。**用 InjectionKey 声明 key 的类型。provide 和 inject 都按这个类型检查：

```js
export const ThemeKey: InjectionKey<Ref<'light' | 'dark'>> = Symbol('theme')
provide(ThemeKey, theme)
const t = inject(ThemeKey)                    // Ref<'light'|'dark'> | undefined
```

注意：inject 的结果可能是 undefined。检查它，或者传入默认值。泛型组件的写法见[第 18 章](/chapters/18-patterns)。

### 21.5 用 vue-tsc 检查类型

tsc 不能读取 `.vue` 文件。vue-tsc 把 .vue 文件转换为 TypeScript，然后检查类型。按下面的步骤做：

1. 在编辑器中安装 Vue - Official 插件。
2. 在项目中安装 `vue-tsc`。
3. 在构建前运行 `vue-tsc --noEmit`。

::: deep 进阶类型写法
```ts
// 1. 给插槽声明类型
const slots = defineSlots<{
  default(props: { item: Todo; index: number }): any
  empty(): any
}>()

// 2. 获取子组件实例的类型
import MyModal from './MyModal.vue'
const modal = useTemplateRef<InstanceType<typeof MyModal>>('modal')
modal.value?.open()                         // open 来自子组件的 defineExpose

// 3. 为全局属性声明类型（模块扩充）
declare module 'vue' {
  interface ComponentCustomProperties {
    $t: (key: string) => string             // app.config.globalProperties.$t
  }
}

// 4. 组合式函数的参数类型
import type { MaybeRefOrGetter } from 'vue'
function useTitle(title: MaybeRefOrGetter<string>) {
  watchEffect(() => { document.title = toValue(title) })
}
```

路由 meta 的类型声明见[第 20 章](/chapters/20-router)。
:::

::: pitfalls
1. 不要 import `defineProps`。原因：它是编译宏，编译器在构建时替换它。import 会产生警告。
2. 在 Vue 3.5 之前，解构 defineProps 的结果后数据不更新。在 3.5 及以上，解构的结果是响应式的。你可以写默认值：`const { size = 'md' } = defineProps<...>()`。
3. 在类型声明中使用接口，或使用本项目文件中的类型。原因：旧版本编译器不能解析复杂的外部类型。
:::

::: summary
- defineProps、defineEmits、defineModel、defineExpose 和 defineSlots 是编译宏，不需要 import。
- 用泛型参数声明 props 和事件：`defineProps<{ ... }>()`。编译器生成运行时声明。
- defineModel 的类型参数声明 v-model 的类型。required 去掉 undefined。
- InjectionKey 为 provide/inject 声明类型。useTemplateRef 为模板 ref 声明类型。
- 用 vue-tsc 检查 .vue 文件的类型。
:::
