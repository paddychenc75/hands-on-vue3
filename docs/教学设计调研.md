# 怎样教 Vue 效果最好：调研结论和课程改法

## 一、为什么现在学起来费劲（诊断）

| 问题 | 数据 | 违反的原则 |
|---|---|---|
| 全部 27 章没有一张原理图 | 0 张 SVG 图 | 双重编码 / 多媒体原则 |
| 基础内容和“深入”内容混在一起，同样醒目 | 共 52 个“深入”小节，全部展开 | 认知负荷：分段原则、一致性原则 |
| 很多章节先给 API 和代码，后讲要解决的问题 | 大部分章节开头直接讲用法 | 预训练原则；先建立问题，再给方案 |
| 只有最后一章有测验，章内没有回忆练习 | 章内自测 0 道 | 检索练习效应 |
| STE 短句让因果关系断开 | 每句只讲一件事 | 信号原则（需要用图和结构补足关联） |

## 二、调研结论（按证据强度排序）

1. **多媒体原则（Mayer）**：图和文字一起出现，比只有文字学得更好。图要画机制（数据怎样流动、顺序是什么），不要画装饰。图的说明文字放在图的旁边（空间邻近原则）。
2. **认知负荷和分段**：一次只给学习者一块内容。把可选的高级内容折叠起来（一致性原则：删除或隐藏不必要的内容）。先教关键概念的名字和作用（预训练原则）。
3. **样例学习（worked examples）**：初学者先看完整的样例，再做“补全题”，最后独立完成。这比直接做题效率更高。
4. **检索练习**：做题回忆比重读更能记住内容。每章结束时做 2–3 道小题，并立即给出解析。
5. **PRIMM（预测 → 运行 → 研究 → 修改 → 编写）**：编程教学中，先让学习者预测代码的结果，再运行，学习效果更好。
6. **间隔复习**：学完一段时间后再复习，比集中复习记得更久。
7. **“概念机器”可视化**：编程原理（例如响应式、调度队列、diff）用可视化的状态变化来教，比只看代码更容易理解。

## 三、课程怎样改（本次优化）

- **每章加 1–2 张原理图**：内容是这一章的核心机制。例如：ref 和解构为什么丢失响应式；调度队列的时间线；keyed diff 的步骤。
- **每章开头加“为什么需要它”**：先讲没有这个功能时会出什么问题，再讲用法。
- **“深入”内容默认折叠**：主线变短。学完主线后再展开。左侧目录有“展开全部深入内容”开关。
- **每章结尾加 2–3 道自测题**：以“预测输出”和“找错误”为主，答完立即显示解析。
- **首页加入“怎样学效果最好”**：先看图、第一遍跳过深入、先预测再运行、不看书自测、间隔复习。
