### P1 必改（4 条）

**P1-1　模板 ref 放在第 3 章，用到了第 5、6 章才讲的 onMounted、onUnmounted、子组件和 defineExpose**
- 位置：`#refs` 3.4"模板 ref：访问 DOM 元素"；`#refs` 3.3 markRaw 场景；对照 `#lifecycle` 6.2。
- 现象：3.4 的最小代码就是 `onMounted(() => { input.value.focus() })`，后面有一张"setup / onMounted / onBeforeUnmount / onUnmounted 时 ref 的值"表，还有"父组件让子组件的输入框获得焦点……用 defineExpose"的场景。3.3 的 markRaw 场景写的是 `const el = useTemplateRef('chart'); onMounted(() => { board.chart = markRaw(echarts.init(el.value)) })`，并注明"模板 ref 见 3.4 节"。第 3 章的 4 条目标和 5 道自测都不涉及模板 ref。第 6 章 6.2 的最小代码又讲了一遍 `useTemplateRef('box')`、"setup 中：null"。
- 为什么是问题：学习者第一次看到 onMounted、onUnmounted、子组件实例时，没有任何前置解释（生命周期在第 6 章，组件在第 5 章）。这正是"用法要放在恰当位置"想避免的情况。同一个知识点分在两章讲，第 3 章这一遍没有目标、也没有题检验。
- 改法：
  1. 把 3.4 整节移到第 6 章，放在 6.2 之后，编号为 6.3"模板 ref：在 onMounted 中读取元素"。合并 6.2 开头那段重复的 useTemplateRef 代码。
  2. 把"父组件调用子组件的 focus"这个场景（defineExpose）移到第 5 章 5.6"选择通信方式"。5.6 的表格里已经有"defineExpose + ref"这一行。
  3. 3.3 的 markRaw 场景改为不依赖 DOM 的例子，例如 `board.client = markRaw(new WebSocket(url))`，删除"模板 ref 见 3.4 节"。

- 为什么是问题：学习者在第 3、6、7、11 章做"显示后聚焦""修改后读高度"时，会碰到 `inputRef.value` 为 null 或读到旧高度，却还不知道解决方法。用法被原理章"扣住"了，违反"先用法后原理"。

**P1-3　小节"已读"会虚高：点目录里的小节链接，前面没读过的小节也被记为已读**
- 位置：页面脚本 `markRead()`（约第 8279 行）；桌面目录 `ol.subs`。
- 现象：Playwright 在 1280px 下，新会话中点击目录"5.6 选择通信方式"，2.5 秒后 `secRead.comm` 是全部 6 个小节（5.1–5.6）。用跳转直接定位到第 4 章自测，第 4 章 4 个小节和第 3 章 4 个小节都被记为已读，进度显示"已读 8 / 133 小节"，而学习者一个小节也没读。原因：`markRead` 在滚动停止 400ms 后，把视口内每一章中"标题在阅读线以上、结尾在视口 85% 以上"的小节全部记为已读，没有停留时间，也不区分跳转和阅读。
- 为什么是问题：第 14 版加小节进度，就是让学习者知道"哪里还没读"。跳读或回头查一个小节后，整章变成"✓ 已读"，这个信号就失效了。复习、续学都可能依赖它。
- 改法：
  1. 只记录"阅读线从标题经过到小节结尾"的小节：滚动时记下每个小节被阅读线经过的累计时间。
  2. 累计时间达到"该小节主线字数 ÷ 600 字/分钟"（约为预计阅读时间的一半）才记为已读。
  3. 目录点击、hash 跳转、"回到上次位置"触发的滚动结束后，不运行 `markRead`；用户下一次滚轮或触摸后再开始计时。
  4. 在 t4.js 里加两个测试：点小节链接后前面的小节不变为已读；匀速滚过一节、停留足够时间后变为已读。

**P2-6　6 条"写 / 编写 / 配置"类目标只用选择题检验**
- 位置：目标列表（按 `data-checks` 统计）。
- 现象：没有挂任何练习的 6 条是：第 8 章"写一个指令，并读取 binding 的 value、arg 和 modifiers"（sc:4、sc:5），第 10 章"编写一个带选项的插件"（sc:2、sc:3），第 11 章"用 defineModel 写一个可以复用的输入组件"（sc:3）和"写一个带异步校验的 useForm"（sc:4），第 14 章"写一个函数式组件"（sc:6），第 19 章"配置路由表"（sc:1、2、4）。另外，第 17 章"写一个递归组件和一个泛型组件"的练习只练递归，泛型只有 sc:4；第 21 章"用虚拟列表显示一万行数据"也只有 sc:0。
- 为什么是问题：目标的动词是"写"，题目只要求"认出"。目标和评测的认知层级不一致，打勾不能说明学习者会写。
- 改法：二选一。一是把动词改为可以用选择题检验的"说明 / 选择 / 判断"，例如"判断插件中哪些代码在 install 中运行"。二是给其中最常用的 4 条（指令的 binding、插件选项、函数式组件、路由表）各加一道 1–2 行 TODO 的补全题，复用这些章已有的实验台代码。

**P2-7　练习都在标题里写出了要用的 API，缺少"选择用哪个 API"的练习**
- 位置：全部 54 道练习的标题和题面。
- 现象：标题如"用 computed 算总价""用 KeepAlive 保留标签页的状态""用 shallowRef 保存大数组"，题面如"用 computed 定义 total"。修复题也在第 1 级提示中直接说出 API。
- 为什么是问题：真实开发中最难的一步是从现象判断该用哪个 API。练习只在"已知用什么"的条件下练"怎么写"，没有辨别练习（discrimination），交错效应也就发挥不出来。学习者反馈的"API 缺少使用层"，一部分就是这个缺口。
- 改法：
  1. 每个阶段末尾加一组 4 道"看现象选方案"的练习，题面只写现象。例如阶段二："切换标签页后，输入框的文字丢失""弹窗被父元素的 overflow: hidden 裁切""关闭弹窗时没有动画""组件卸载后控制台还在打印"。学习者在同一个编辑器中选择并修复，判题和现在一样。
  2. 修复题的标题只写现象，例如把"修复：定时器泄漏"改为"修复：隐藏后数字还在增加"。第 1 级提示改为指向现象和原因，不直接说出 API 名字。

**P2-8　间隔复习只要答一题就算"已复习"，答错不影响下次复习时间，复习题按章成组**
- 位置：测验脚本 `after(sid)` → `markReviewed()`；`buildSession()`。
- 现象：复习时，每答一道题就调用一次 `markReviewed(sid)`，答对答错都把这一章推进到下一档（2 → 7 → 30 天）。章内自测答错的题不会被优先抽到。`buildSession` 按到期章逐章拼接，每章 3 题连在一起出现。
- 为什么是问题：间隔复习的作用来自"答错的内容更早再见"。现在答错也推进到 30 天，薄弱点反而最晚复习。按章成组，学习者看到第一题就知道后两题考哪一章，交错效应也会减弱。
- 改法：
  1. 一章的 3 道复习题都作答后，才更新 `revAt`。全对时 n + 1；有错时 n 归 0，2 天后再复习。
  2. 抽题时优先抽 `store.sc` 和 `quiz3` 中答错过的题。
  3. 所有到期章的题拼好后整体打乱，再显示。
  4. 复习结束时显示"第 3 章有 1 题答错，2 天后再复习"。

**P2-9　手机上看不到小节列表，吸顶区占屏 17%，编辑器字号 13px**
- 位置：CSS `@media (max-width: 900px) { .toc ol.subs { display: none !important; } }`；`nav.toc` 在 390px 下的吸顶区；`.ex textarea`。
- 现象：390px 下，第 14 版的小节进度只剩章节标签上的"0/4"，学习者不能看到哪几节没读，也不能跳到某一节。吸顶区（进度、两个开关、章节标签）高 140px。练习编辑器 `font-size: 13px`，iOS Safari 在聚焦字号小于 16px 的输入框时会自动放大页面。练习按钮高 33px。
- 为什么是问题：手机是碎片时间复习的主要设备。小节进度在手机上没有用处；自动放大后，学习者要手动缩回才能看到判题结果。
- 改法：
  1. 点击当前章标签时，在吸顶区下方展开这一章的小节列表（带 ✓ 和 ○）。
  2. 向下滚动时，把吸顶区收起为一行"第 4 章 · 2/4 · ≡"，向上滚动时再展开。
  3. 手机宽度下 textarea 用 16px，可以保留桌面的 13px。
  4. 练习按钮的最小高度设为 40px。

**P2-10　首页的"章节结构"和"写作规则"与第 13 版重排后的实际不一致**
- 位置：首页"每一章的结构"一行；`details.ste` 的写作规则；首页第一段。
- 现象：首页写"目标→为什么需要它→图解→说明→实验台→练习→深入（可选）→注意→自测→小结"。实际结构是：目标 → 阅读时长 → 类比 → 术语 → 为什么，然后每个小节按"说明 → 最小代码 → 场景 → 注意 → 实验台/练习 → 深入"，最后是"注意"汇总 → 自测 → 小结。写作规则写"'注意'写在相关步骤之前"，正文的"注意"都写在代码和场景之后。首页还写"本课程有 4 个阶段和 27 章"，正文实际是 25 章 + 综合实战，进度条也写"已完成 0 / 27 章"，把测验算成了一章。
- 为什么是问题：首页是学习者对课程结构的先行组织者（advance organizer）。说明和实际不一致时，学习者找不到"深入"和"注意"的位置。写作规则自相矛盾，也会让审稿人按错的标准检查。
- 改法：把结构一行改为两行："每章：目标 → 类比 → 术语 → 为什么需要它 → 各小节 → 注意（汇总）→ 自测 → 小结""每个小节：问题 → 最小代码 → 场景 → 注意 → 实验台 / 练习 → 深入（可选）"。把写作规则改为"'注意'紧跟在它所说明的代码之后，在实验台和练习之前"。首页改为"25 章、1 个综合实战和综合测验"，进度条的分母不计测验和速查表。

**P2-11　答题和判题结果没有 aria-live，读屏软件不播报**
- 位置：`.sc`（自测、先猜）、`.ex-res`（练习结果）、`.tabs`（实验台标签页）。
- 现象：脚本检查，页面上 `[aria-live]`、`[role=status]`、`[role=alert]` 的数量为 0。解析开头虽然写了"正确。"或"不对。"，但展开时没有播报。用键盘在第 3 章自测中按 Enter 作答后，选项按钮全部变为 disabled，焦点掉到 `<body>`。实验台的 `.tabs` 没有 `role="tablist"`。
- 为什么是问题：读屏用户作答后听不到"对 / 错"，焦点又回到页面开头，等于做了一道没有反馈的题，还要重新找回位置。
- 改法：给 `.sc-x` 和 `.ex-res` 加 `role="status"`（`aria-live="polite"`）；`paintSc` 中把选项改为 `aria-disabled="true"`，不用 `disabled`，并把焦点移到 `.sc-x`（加 `tabindex="-1"`）；被选的选项加 `aria-pressed="true"`；`.tabs` 加 `role="tablist"`，按钮加 `role="tab"` 和 `aria-selected`。

### P3 可选（5 条）

**P3-1　同一 API 在两章完整讲两遍**

## 建议的执行顺序

1. P1-3（已读进度）和 P1-4（目标挂错题）：只改脚本和数据，半天可以完成，直接影响进度信号的可信度。
2. P1-1、P1-2（模板 ref 和 nextTick 搬家）：一次完成，同时处理 P2-2 中第 3 章的实验台拆分。

4. P2-5、P2-7：新增练习，工作量最大，收益也最高。
